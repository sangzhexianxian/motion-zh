# 财经解读 · 竖屏信息卡

> 24 秒竖屏信息卡模板。封面 → 数据卡 → 方向卡 → 收尾。
> 1080×1920 / 30fps / 中文 / 无外部依赖 / 不联网。

## 给 AI 助手的操作说明

### 1. 读这三个文件再动手

| 文件 | 作用 |
|---|---|
| `guide.json` | 适用类型、素材角色、时长策略、缺失输入处理 |
| `params.schema.json` | 可替换字段、类型、**中文字符上限** |
| `presets/demo.json` | 一份可直接跑的示例参数 |

不要凭模板名猜参数。所有能改的东西都在 `params.schema.json` 里。

### 2. 填写参数

按用户给的内容填 `params.schema.json` 声明的字段，写到哪里都可以，最后交给 `inputs`。

**容量是硬约束，不是建议：**

| 字段 | 上限 |
|---|---|
| `title` | 24 字，最多 2 行，每行建议 ≤12 字 |
| `stats` | 1–2 条；`value` ≤8 字符，`label` ≤14 字 |
| `directions` | 1–3 条，每条 ≤16 字，单行 |
| `summary` | ≤20 字 |
| `cta` / `brand` / `issue` / `date` | ≤12 / 8 / 12 / 12 字 |

超容量时**改写文案**，不要靠缩小字号硬塞。字数超了画面会挤，这是本模板最容易出事的地方。

### 3. 校验（必须）

```bash
python3 scripts/check_zh.py --params <你的参数.json>
```

它会检查：字段容量、断行后每行字数、标点是否落在行首、数据条数、必填项。
退出码非 0 就改文案，不要跳过。

### 4. 预览再出片

```bash
node tools/render_probe.js            # 抽 9 帧到 probe/
```

看四类问题：
1. 有没有文字贴边或被裁切
2. 标题断行是否把词切断了（「降准落|地」这种）
3. 数据卡两条是否都完整入场（第 2 条在 S2 开始后 1.9s）
4. 结尾是否成立（品牌行 + 总结 + CTA + 水印）

### 5. 渲染

模板的 `runtime.entry` 是 `src/index.html`，暴露三个全局：

| 全局 | 说明 |
|---|---|
| `window.MP` | 参数对象（在页面脚本执行**前**注入） |
| `window.SEEK(t)` | 把画面定格在第 t 秒（逐帧渲染入口） |
| `window.DURATION` / `window.FPS` | 24 / 30 |

帧驱动必须调 `SEEK(t)`，**不要依赖 CSS 动画**——逐帧截图时 CSS 动画不会被定格。

## 设计约定（改模板前必读）

- 所有动效在 `SEEK(t)` 里用 `transform` / `opacity` 显式设置，禁止 `@keyframes`、`transition`
- 字号用 `fitText()` 按 `measureText` 自适应，中文断行用 `wrapZh()`（带标点禁则：`，。、；：？！）】》」』%` 不出现在行首）
- 配色只用 `accent` / `accent2` 两个可变色，其余固定深色底
- 不引入外部图片、字体文件、网络请求

## 合规

- 不写收益承诺、不写涨跌点位
- 示例数字必须标「（示例）」
- 数字要能说清口径，不要给孤立的大数字
