# 字幕卡片 · 给 AI 助手的操作说明

人看 `README.md`。这份是给你（助手）的。

## 什么时候用这个模板

用户手上**已经有字幕**（SRT、ASR 转写、剪映导出、逐句手打），想要一条竖屏片，但**不想把字幕重新拆成标题和要点**。

这个模板不改一个字幕，只负责让每一句放得下、读得到。

## 三步

### 1. 拿字幕

优先级从高到低：

1. **SRT 原文** —— 整段粘进 `srt` 字段，模板自己解析时间轴。**不要转成 JSON**，不要手动算秒数。
2. **逐句文字 + 大致时长** —— 转成 `subtitles` 数组 `[{start, end, text}]`。
3. **只有一段文字、没有任何时间信息** —— 按每句 3 秒平均分配，并在交付时**明确说明「时间是估算的」**。

不要因为「格式不标准」就拒绝。SRT 里的中文逗号、句号、多行字幕、带 `<i>` 标签，模板都能处理。

### 2. 填参数

```json
{
  "srt": "1\n00:00:00,000 --> 00:00:04,440\n第一句\n\n2\n...",
  "brand": "栏目名（≤8 字，可留空）",
  "issue": "期号（≤12 字，可留空）",
  "title": "顶部小标题（≤24 字，可选，不占时间轴）",
  "keywords": ["要强调的词，≤12 个，每个 ≤12 字"]
}
```

规则：

- **`srt` 原样粘**，不要改写字幕、不要合并句子、不要动时间码
- `brand` / `issue` / `title` 用户没提就留空或默认，**不要追问**
- `keywords` 从字幕里挑真正关键的词（数字、结论、病名、专有名词）。**超过 8 个会显得花**
- 单条字幕超过 36 字，模板会按标点自动切成两屏 —— **你不要手动拆**

### 3. 渲染后检查这四件事

1. 总时长 = 最后一句结束 + 0.8 秒（对不上说明时间码解析有问题）
2. 抽 3 帧看：**每行不超过画面宽度、标点不在行首、末行不是孤零零一个字**
3. 关键词命中处有没有变色（`keywords` 写错字就永远不命中，静默失败）
4. 句与句之间的空档有没有黑屏（有 hold 机制，正常不会有）

## 硬约束

| 不要做 | 原因 |
|---|---|
| 改写字幕文字 | 字幕必须跟音轨逐字对齐，改了就不准 |
| 手动算每句秒数（有 SRT 时） | 你算不过时间码，而且会引入累积误差 |
| 为了「更好看」调整时序 | 音画会错位，用户一眼就能看出来 |
| 缩字号硬塞长句 | 模板自己会切屏，缩字号只会让人看不清 |

## 这个模板不做的事

- 不出音轨（配音是下游工序，成片与原音轨在剪辑软件里合）
- 不做图表、数据大字卡、章节结构（那是 `finance-cards` 那类模板的活）
- 不改字幕内容（含错别字、口语病句 —— 要改请在源文件改）
